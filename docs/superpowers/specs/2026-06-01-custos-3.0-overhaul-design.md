# Custos 3.0 — Overhaul Design

**Date:** 2026-06-01
**Author:** Paulus Platov (dybekych@gmail.com)
**Status:** Approved design → ready for implementation plan
**Version target:** `3.0.0`

---

## 1. Summary

Custos is a Windows forensic anti-cheat scanner for Unturned servers, built on
Electron 42 + React 19 + TypeScript 5.9 + Vite. This effort takes the existing,
functionally-working app and:

1. Resets the GitHub repository to a clean state (fresh history, `main` + `dev`
   branches) while preserving all published releases so existing download links
   keep working.
2. Adds proper repository hygiene (README, .gitignore, LICENSE, CI, templates).
3. Restyles the entire desktop UI to match the official website
   (`dybeky/custosweb`) design system **exactly**.
4. Refactors the internals for clarity, safety, and testability **without
   changing what any scanner does**.
5. Strengthens detection so the scanners reliably catch the known cheat targets
   (the existing `keywords.json` list) plus researched variants — "no chance"
   against the hack list.
6. Updates dependencies and adds meaningful test coverage.

All work ships as a single coordinated `3.0.0` release, executed in phases 0→5
in order. Every scanner's purpose is preserved; functions are improved, not
removed.

**Non-goals:** No ground-up rewrite. The Electron process boundaries
(main/preload/renderer, `contextIsolation: true`, `nodeIntegration: false`) are
already correct and are kept. No new platforms (Windows-only remains). No
backend/telemetry added.

## 2. Context & current state

- **Repo:** `dybeky/custos` (public). Default branch `master`. Local folder is
  **not** currently a git repo.
- **Releases:** `2.1.1`→`2.2.2` published, each with installer assets. Tags
  `2.1.0`→`2.2.2` exist. These MUST survive the reset.
- **Website / style reference:** `dybeky/custosweb` (private). Design system is
  *"pastel forensic console"*: dark indigo background, periwinkle/lavender
  accents, MuseoModerno typeface, lowercase body / uppercase display, soft
  glows and scan-line motifs.
- **Hack list (detection targets):** `resources/keywords.json` —
  `patterns`: undead, melony, fecurity, ancient, medusa, mason, midnight,
  fatality, memesense, xnor, aimbot, wallhack, triggerbot, norecoil, speedhack,
  hwid_spoofer, unturned_cheat, unturnedcheat, unturnex, uloader, ucheats,
  utools, cheatengine, megadumper, extremedumper, neverlose, nixware;
  `exactMatch`: esp, hwid, spoofer.

### Architecture (preserved)

- **Main** (`src/main/`): all OS access — 14 scanners, services, IPC.
- **Preload** (`src/preload/index.ts`): single frozen `electronAPI` over
  `contextBridge` (24 methods).
- **Renderer** (`src/renderer/`): React Router, Zustand stores, Tailwind,
  i18next, framer-motion. No Node access.
- **Shared** (`src/shared/types.ts`): `IPC_CHANNELS` + DTOs, single source of
  truth.
- **Scanners**: 14 classes extend `BaseScanner`; a `ScannerFactory` singleton
  instantiates them with a shared `KeywordMatcher` + settings.
- **Data flow:** `Scan.tsx` → `SCAN_START` IPC → orchestrator groups scanners
  and runs them with per-group concurrency/timeout → per-scanner `ScanProgress`
  / `ScanResult` events → Zustand store → `Results.tsx` renders + exports.

### Known issues feeding this design (from audit)

- **Latent bug:** scanners grouped for concurrency by matching display **name**
  (`ipc-handlers.ts:254-279`); a rename silently drops a scanner from every
  group and it never runs.
- **Duplication:** `reg query → split → parse` copy-pasted across
  `registry`/`bam`/`amcache`/`shellbags` scanners; identical try/catch/cancel
  block in all 14 scanners; progress-emit boilerplate repeated.
- **God file:** `ipc-handlers.ts` (463 lines) mixes IPC registration + scan
  engine + self-delete logic.
- **Security smell:** all OS commands run through `exec()`/`cmd.exe` with string
  interpolation (no live injection today, but fragile).
- **Duplicated config:** `resources/*.json` ≡ `src/main/config/*.json`
  (byte-identical, hand-synced).
- **Unused aliases:** `@hooks` and friends in `electron.vite.config.ts`; two
  mismatched alias schemes between renderer and node tsconfig.
- **Tests:** only 2 files; all 14 scanners, the orchestrator, and the
  `validateBatchPath`/`escapeBatchPath` security functions are untested.
- **Deps:** `electron-store` v8 (v10 exists, ESM migration); ESLint 8 (EOL) on
  legacy `.eslintrc.json`; `framer-motion` used in a single place.

## 4. Phase 1 — Repo files & structure

### Sole authorship & de-branding
- **Remove the "second contributor."** `package.json` currently sets
  `"author": "COBRA"`. Strip it: Paulus Platov (dybekych@gmail.com) is the sole
  author/contributor across `package.json`, `LICENSE`, README, and all metadata.
  No second-contributor clause anywhere.
- **No Claude as contributor.** No `Co-Authored-By: Claude` trailer on any
  commit, and no "Claude"/AI attribution anywhere in the program, package
  metadata, README, or docs.
- **Remove all COBRA-specific branding** so Custos is a standalone product (not
  tied to "COBRA servers"), matching how the website presents it as its own
  product:
  - `package.json:6` — replace `"author": "COBRA"` with `"author": "Paulus Platov"`.
  - `src/main/index.ts:71` — `setAppUserModelId('com.cobra.custos')` → a neutral
    id (e.g. `com.custos.app`).
  - `electron-builder.yml:1` — `appId: com.cobra.custos` → matching neutral id.
  - Generic copy like "MADE FOR UNTURNED SERVERS" stays (already not
    COBRA-specific).

### Repository files
- **README.md** — a **tutorial-style guide, English only** (no multilingual
  versions). **Written from my own reading and understanding of how this program
  actually works — NOT copied from the website.** The website's *tone/voice*
  (guardian / forensic-console, lowercase where it reads well) may inform the
  styling, but all content is derived from the source code: what each scanner
  inspects, what the scan flow does, what the results mean. Structured as a
  walkthrough: what Custos is → download/install → run a scan step by step →
  read the results → settings/utilities → build from source → disclaimer (admin
  rights, intended use). Screenshots, download badges linking to Releases.
- **.gitignore** — proper Node/Electron/Vite ignore (node_modules, out, dist,
  `*.tsbuildinfo`, build artifacts, OS files, local env).
- **LICENSE** — MIT, "Paulus Platov".
- **CONTRIBUTING.md** — branch model (`dev` for work, PR to `main`), commit
  conventions, how to run/test.
- **GitHub Actions CI** — on PR/push: `typecheck` + `lint` + `test` + `build`.
- **Issue / PR templates** — minimal bug-report + feature templates.

### Structure cleanup
- **De-duplicate config:** make `resources/*.json` the single source of truth;
  remove `src/main/config/*.json` (or generate at build), and simplify
  `config-service.ts:getResourcePath()` accordingly.
- **Fix path aliases:** pick one alias scheme, wire it consistently across
  `electron.vite.config.ts` + tsconfig files; remove unused `@hooks` etc.
- Remove dead back-compat surface (`SYSTEM_GET_WINDOWS_VERSION` channel +
  `getWindowsVersion` alias + `WindowsVersionInfo` type alias) unless still
  referenced.

### Acceptance
- README/LICENSE/CONTRIBUTING/.gitignore present and accurate.
- CI green on `dev`.
- Only one copy of each config JSON; app still loads config in dev and packaged
  builds.

## 6. Phase 3 — Refactor (function preserved)

**Goal:** clearer, safer, testable internals. Behaviour unchanged except where a
bug is fixed.

1. **Fix the grouping bug.** Key concurrency groups off the stable `ScannerName`
   id (group metadata moves into `ScannerFactory`/scanner definitions), not the
   display name. Add a test asserting every scanner lands in exactly one group.
2. **Split `ipc-handlers.ts`** into:
   - thin IPC registration (`ipc-handlers.ts`),
   - `src/main/scan-orchestrator.ts` (grouping, concurrency, timeout, progress),
   - `src/main/services/self-destruct.ts` (batch self-delete + path escaping).
3. **`RegistryQueryScanner` base** (extends `BaseScanner`): one shared
   `reg query`/parse helper; migrate `registry`/`bam`/`amcache`/`shellbags`.
4. **`BaseScanner` template method**: `runScan()` wraps the identical
   try/catch/cancelled block; add `emitProgress()` + a `mapWithConcurrency()`
   util. Remove ~15 lines/scanner of boilerplate.
5. **Security — `execFile` + arg arrays.** Add `execFileAsync(file, args[])` in
   `async-exec.ts`; migrate `reg query` and similar call sites away from
   shell-string `exec` (removes the injection class + the `chcp 65001 &&` hack).
6. **Robustness:** Zod-validate external-command JSON (`process`/`bam`
   PowerShell output); replace silent `catch {}` with `logger.debug`; surface
   the real error in `runScannerWithTimeout`; collapse to a single
   uncaught-exception handler; make date locale follow the user's language
   setting consistently.

### Acceptance
- All existing scans produce equivalent results to 2.2.2 on a test machine.
- New unit tests (grouping, base-scanner template) pass.
- `typecheck` + `lint` clean.

## 7. Phase 4 — Detection improvements (research-backed, aggressive)

**Goal:** "no chance" against the hack list. Maximize true-positive detection of
the known cheats and their evasion variants; document every change with its
source. Research and apply broadly across all scanners.

### Inputs
- The existing `keywords.json` targets are the **floor**, not the ceiling.
- Research current public forensic techniques and known Unturned cheat ecosystem
  artifacts for each scanner domain: BAM, AmCache, Prefetch, ShellBags, DNS
  cache, Recent files, Steam, registry, process, VM-evasion, browser history.

### Work
- **Expand the indicator set:** add known aliases, alternate spellings, loader
  /injector names, seller domains, and renamed-binary heuristics for each cheat
  on the list (undead, melony, fecurity, ancient, medusa, mason, midnight,
  fatality, memesense, xnor, neverlose, nixware, unturnex, uloader, ucheats,
  utools, cheatengine, megadumper, extremedumper, hwid spoofers, esp/aimbot/…).
- **Add artifact sources** where a cheat leaves traces a scanner currently
  misses (e.g. additional registry hives, MUICache, UserAssist, SRUM, journal,
  cleared-prefetch detection, timestamp-anomaly heuristics).
- **Anti-evasion:** detect cleared/missing artifacts and spoofing tools as
  signals in their own right (e.g. HWID spoofer presence, prefetch wiped, BAM
  cleared).
- **Keep keyword matching robust:** case-insensitive, word-boundary aware,
  resistant to simple obfuscation (separators, padding) without exploding false
  positives.
- Every added indicator / technique is documented in a
  `docs/detection/` note with its source and which scanner consumes it.

### Detection accuracy stance
- Bias toward catching everything on the list ("no chance"), accepting that
  aggressive matching may raise some borderline flags; results UI already
  distinguishes detections clearly. Generic terms (esp/hwid) remain
  exact-match to avoid runaway false positives.

### Acceptance
- For each named cheat on the list, at least one scanner has a documented
  detection path covering its primary artifact + at least one evasion/rename
  variant.
- Detection changes documented in `docs/detection/`.

## 10. Risks & mitigations

| Risk | Mitigation |
|------|------------|
| Repo reset orphans releases / breaks download links | Releases live independently of branch history on GitHub; verify all download URLs post-reset before deleting `master`. |
| `execFile` migration changes scanner output | Migrate scanner-by-scanner; compare results against 2.2.2 baseline on a test machine. |
| Aggressive detection raises false positives | Keep generic terms exact-match; word-boundary matching; clear results UI; document each indicator. |
| `electron-store` v10 ESM migration breaks settings load | Isolate in one module; test settings read/write before/after. |
| Restyle regresses usability of dense data views | Match palette + feel; verify tables/result lists stay legible (website parity is for look, not layout density). |

---

## 11. Execution model

Single implementation plan, phases 0→5 in order, one coordinated `3.0.0`
release. Subagents may be used for parallelizable, independent work (e.g.
per-scanner refactors, detection research per domain, component restyles) where
it speeds things up without shared-state conflicts.
